# ESP32 毫米波雷达呼吸滤波 v8

本包基于公开仓库 `Radar_analyze_test/main_bt_7.cpp` 的接口和协议设计 v8 独立实现。

原始仓库：https://github.com/baimojushi/Millimeter-wave-radar-solution-iteratio

> 研究原型，未经真实雷达、人体呼吸参考设备、设备长时间运行及医疗标准验证。**不得用于疾病诊断或呼吸暂停报警。**

## 1. 直接使用

**PlatformIO 项目**：打开本目录并使用 `pio run` 编译，主程序位于 `src/main.cpp`，算法头文件位于 `include/radar_resp_filter_v8.h`。目标开发板为经典 ESP32 DevKit，支持蓝牙经典协议 SPP。

**Arduino IDE 项目**：打开 `ArduinoSketch/RadarV8/RadarV8.ino`，安装支持经典蓝牙的 ESP32 Arduino 开发板核心，选择经典 ESP32 开发板后编译。

**向原仓库增量集成**：将根目录的 `main_bt_8.cpp` 和 `radar_resp_filter_v8.h` 放到 `Radar_analyze_test/` 同一目录。避免同时编译 v7/v8 两个含 `setup()`/`loop()` 的源文件。

固件引脚配置沿用 v7：UART2 接收 GPIO16、发送 GPIO4，雷达串口速率 1382400；按钮 GPIO17，上拉，按下为低电平。USB 调试串口 115200，蓝牙名称 `ESP32-Radar-v8`。

## 2. 算法链路

1. 校验 TF 帧头与数据异或校验、长度上限和浮点数有效性。
2. 处理 `[-π,π]` / `[0,2π]` 常见相位折返；若真实相位步长超过 0.90 rad/样本，则丢弃当前历史窗口并重建。
3. 一阶指数平滑（系数 0.20）后，累积 1000 个相位样本；首次稳定估计需约 22 秒。
4. 对 20 秒样本进行最小二乘线性去趋势，检测时间基准是否接近 50 Hz。
5. 在 100~333 个样本的延迟范围内，计算**逐延迟能量归一化自相关**，搜索局部峰值。
6. 对候选周期进行正交正弦/余弦投影，独立检查该频率的能量占比；遇到强次谐波歧义时拒绝输出或按证据选择长周期。
7. 检查幅度、频谱纯度、自相关相关度、前后半窗幅度变异系数；大幅跳变要求连续两次确认。
8. 无人、数据超时、异常幅度、采样率偏差或置信度不足时立即输出 `br=0` 和具体原因 `q`。

**重要改变**：v8 不再使用 63 抽头的希尔伯特/带通级联，改为频率正交投影和双半窗稳定性检查。JSON 的 `hil_ph` 字段为拟合呼吸分量相位，用于兼容旧绘图；其物理意义已变更。

## 3. 输出协议（每 100 ms 一次）

```json
{"t":12345,"raw":0.3210,"lp":0.3000,"hil_ph":1.23,"br":16.05,"conf":0.92,"amp":0.64,"cv":0.08,"score":0.88,"fs":50.00,"lag":186.90,"q":"ok","human":1,"n":1000,"frames":5432,"crc_err":0,"key_drops":0,"calc_us_max":25000}
```

- `br`：可信时显示呼吸率，单位 次/分钟；**0 表示无有效估计，不表示停止呼吸**。
- `q`：`warmup / ok / no_human / stale / bad_input / motion / timebase / low_signal / low_quality / ambiguous / transition`。
- `conf`：归一化自相关，范围 0～1。`amp`：正弦拟合幅度，单位 rad。`cv`：前后半窗幅度变异系数。
- `score`：v8 无量纲质量分数（0～1），已改变 v7 的 `amp×conf` 定义；**旧阈值与新阈值不兼容**。
- `fs`：实际接收时间估算的相位帧率。`human`：1 有人、0 无人、-1 未收到人体状态帧。`lag`：最终延迟样本数。
- `calc_us_max`：自开机以来单个相位包调用滤波计算的最大耗时（微秒），用于实机评估任务调度和串口积压。
- `crc_err`：含校验失败与非法长度计数。
- `evt=key` 独立帧：`br_key`、`n_keys`、`lag_err`、`lag_valid`、`gap`。间隔 1.8～7.5 秒（约 8～33 bpm）支持参考标记。

## 4. 参数与权衡

| 参数 | v8 默认 | 说明 |
|---|---:|---|
| `FS` | 50 Hz | 必须与雷达真实相位输出速率匹配 |
| `WINDOW` | 1000 | 20 秒观察窗，约 22 秒首次估计 |
| `UPDATE_STRIDE` | 100 | 2 秒重估一次，输出仍为 10 Hz |
| `LAG_MIN / LAG_MAX` | 100 / 333 | 有效呼吸范围约 9～30 bpm |
| `STALE_MS` | 700 ms | 无相位包时旧输出失效 |
| `STEP_LIMIT_RAD` | 0.90 | 突发相位变化门限 |
| `MIN_RMS_RAD` | 0.035 | 低信号时拒绝 |
| `MIN_ACF` | 0.35 | 相关峰质量下限 |
| `MIN_PURITY` | 0.30 | 单频能量占比下限 |
| `MAX_CV` | 0.60 | 半窗幅度波动上限 |

参数位于 `radar_resp_filter_v8.h` 顶部，需用真实数据重新标定，**不能直接视为医学或工程设计许用值**。

## 5. 本地运行回归测试

依赖：支持 C++11 的 `g++`；无需 ESP32 硬件即可运行算法和协议模拟测试。

```bash
bash run_tests.sh
```

测试文件：

- `test_v8.cpp`：稳态呼吸、谐波、相位折返、噪声、掉线、无人、NaN/Inf、频率突变；
- `test_protocol_v8.cpp`：TF 数据协议、校验、缓冲长度、残缺包恢复、按键防抖；
- `test_edge_v8.cpp`：范围外频率、时间戳环绕、缺包及异常数据后的恢复；
- `test_stress_v8.cpp`：极端噪声、周期性运动与性能边界探测，**其中周期性运动会产生已知假阳性**；
- `repro_v7_halving.cpp`：仅复现 v7 自相关/倍周期判定代码片段，用于说明原算法问题，不代表完整 v7 固件实测。

`test_stubs/` 是主机端模拟的 Arduino/FreeRTOS 接口，用来进行静态语法编译和协议测试；**不能代替在 ESP32 上构建、烧录和长时间运行验证**。

## 6. 未解决的核心风险

- 单通道相位信号里，周期性身体运动恰好落在呼吸频段时，能够伪装成呼吸。压力测试已复现该假阳性。消除该问题需要额外的距离单元、幅度/多天线特征或独立运动信息。
- 强非周期运动干扰可能令真实呼吸也被静默过滤，降低有效输出率。
- 20 秒观察窗会增加首次检测和变化响应延迟，无法直接用作短时呼吸暂停检测。
- `50 Hz` 依据 v7 源码假设；设备不提供独立采样时间戳时，UART 接收时间只能辅助检测明显的帧率不匹配。
- 原始雷达设备型号、原始 50 Hz 相位流、人工标注真值和平台版本均未提供，尚无实机准确率、资源占用、能耗与稳定性保证。
- 双核心共享数据采用短时临界区复制，但实际经典蓝牙串口和 1382400 波特率输入仍需做板载压力测试。

## 7. 建议实机验收

录制完整的原始 TF 帧、同步参考呼吸带/人工标注、人体检测结果，完成 9、12、16、20、24、30 bpm 各档稳态、突变、坐姿/站姿、离人、手臂运动、周期性机械运动以及 UART 断流测试。

记录平均绝对误差、95% 误差分位数、有效输出率、误判为半频率比例、错误可信输出率、初始稳定耗时、跳变响应耗时、`calc_us_max`、串口丢帧/校验率。基于这些结果再调整阈值并决定是否发布。
